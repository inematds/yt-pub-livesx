Changelog

v3.32.32

Feature:

  • Multiple recipients per channel (Chat IDs separated by commas)
  • Sign up through the bot: user sends "my channel is livesN"
  • Sign-up has an on/off switch controlled from the master

v3.28.32

Feature:

  • Telegram notification by channel: new Chat ID + on/off toggle in the Schedules tab
  • Each published video (clip / import / TikTok) generates a notification with the YouTube link
  • The "Send video" button in the message sends the MP4 (up to 50 MB)
  • Detection and sending run in master-dashboard, with a dedicated bot

v3.27.32

Bug:

  • The designer preview (and thumbnail generation in the scheduler) failed on new machines with "No module named 'PIL'": Pillow wasn’t installed. setup-system now installs python3-pil via apt (the right approach on Ubuntu 24/PEP 668), and the final check verifies the PIL import.

v3.27.31

Bug:

  • Scheduler: video_ids starting with '-' (e.g., -I2kOs0_GCk) were interpreted as flags by yt-clip and caused "unknown option" errors. The scheduler now invokes it with a '--' separator, and yt-clip accepts '--' before the video_id.
  • Scheduler: improved error capture during clipping. Previously, it only saved the last 5 lines (hiding the actual error when yt-dlp printed a lot of '[download]%'). Now it filters download lines, keeps the last 30 relevant lines, and saves the complete output to data/last_corte_error_<video_id>.log.

v3.27.30

Bug:

  • Fix imports_clips_pend on the dashboard: it counted using a set of manifest titles, and manifests with duplicate titles (e.g., all "Video") collapsed to 1 and showed zero pending. Now compares counts (len(manifest) - published_count).

v3.27.29

Feature:

  • New lives12 instance (port 8402) registered in the master dashboard and sync script. yt-scheduler12/yt-dashboard12 systemd services installed. Awaiting config/.env + OAuth credentials.

v3.26.29

Feature:

  • New "Local (inemaimg)" image provider: uses a local API (FastAPI) with flux2-klein/flux2-dev/qwen-edit-2511/ernie/sdxl/sd15 models. Configurable URL per instance (default http://localhost:8000). Same pattern as imkt4/timesmkt3.

v3.25.28

Fixes:

  • Critical fix: scheduler.acquire_lock had a race condition that allowed 2 schedulers to run in parallel → published 2 clips per slot instead of 1. Now opens the lock without truncating it and only writes the PID after flock.

v3.25.27

Features:

  • “Fetch new” now uses an incremental scan with early break: cutoff = MAX(upload_date) known; yt-dlp stops as soon as it sees an old video. Fast even on large channels.
  • "include inactive" flag in dashboard for global scan, including disabled channels

v3.24.27

Features (TikTok refactor):

  • New tiktok_videos table with status (pending/downloaded/skipped/error) and automatic migration from legacy tiktok_downloaded
  • Scan separate from download: scan adds videos to the queue (up to 5000 videos per channel), download processes the queue oldest-first
  • Scheduler now only downloads from the queue on schedule (fast); scan manually via the dashboard
  • UI: Queue column (P/B/X/E) per channel; Scan/New buttons per channel + global Full Scan/Get New/Download Queue
  • New endpoints: /api/tiktok/fetch-latest, /api/tiktok/download, /api/tiktok/queue

v3.23.27

Fixes:

  • yt-clip: validates source.mp4 with ffprobe before cutting; removes and downloads it again if corrupted (previously caused a loop of silent empty cuts)
  • yt-clip: checks the ffmpeg return code for each clip; aborts with an error if all fail (previously it falsely reported "completed")

v3.23.26

Fixes:

  • TikTok Scanner: photo posts/slideshows (audio only, no video) were being downloaded repeatedly and leaving orphaned folders without a manifest
  • Now detected during the scan via duration=0 and marked as downloaded; previous orphaned folders cleaned up

v3.23.25

Fixes:

  • Fix: clips_pendentes was never decremented after publishing (imports showed phantom pending items)
  • Recalculates clips_publicados and clips_pendentes based on the actual publicados table

Features:

  • Auto-sync with date filter: new “Starting from” field next to the Auto-sync button
  • Midnight auto-sync only considers live streams published on or after the configured date (prevents reimporting the channel’s entire history)
